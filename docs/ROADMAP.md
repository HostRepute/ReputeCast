## Done so far (M0)

- Schema for every domain (migrations 00001–00010), sqlc, River with a maintenance worker.

## Done so far (W04: sign-in, account and notifications, M1)

- Password reset by email through the System stream, or `reputecast user reset-password` when no provider can send yet; invitations accepted with a password, a passkey, SSO or social sign-in.
- Account & security: profile and photo, email change with verification, password change with the breached-password check, authenticator and passkeys, recovery codes, connected Google/Microsoft/GitHub and SSO sign-ins, active sessions with sign-out, workspaces.
- Notification center: the bell's popover and the full page, per-workspace notifications with read state, preferences per event type for in-app and email.

## Done so far (W01: sending providers & routing, M3)

- Adapters for Amazon SES (SESv2, SNS signature check and subscription handshake, Easy DKIM, configuration-set tracking, VDM flag, AWS status feed), Postmark (batch send, Broadcast stream, basic-auth webhooks, outbound stats as its own reputation), Postal (RS256 signed webhooks via JWKS, message backfill) and generic SMTP (go-mail, DSN/ARF parsing, IMAP and POP3 bounce mailboxes). All pass the shared contract suite (`internal/providers/contracttest`); optional interfaces for quota, domains, suppressions, webhooks, tracking, backfill and status pages.
- Webhook ingest `POST /hooks/{adapter}/{token}`: verify, store the raw payload, 200 at once; a River job normalizes into delivery events, messages, campaign counters, the shared suppression list and provider stats, with dedupe; sweeper and 90-day retention.
- Health job: quota and rate discovery, call windows, outage detection (error rate or two failed probes), automatic failover per stream policy, held Broadcast shares with wait/move/cancel decisions, recovery after ten healthy minutes, rejected credentials, webhooks silent after six hours with a diagnosis and backfill, incidents, notifications and system audit entries.
- Routing per stream (primary, weighted split, conditions on mailbox provider/list/sender domain, fallback, failover policy), bulk-terms validation with an acknowledged override, route tester; warm-up plans with guards, slowdowns, share steps and a daily job; suppression sync per provider; provider-side tracking checks; community and generic HTTP adapters (instance admins).
- Screens: Providers (healthy, outage, webhooks silent, rejected credentials, empty, loading), Routing & failover (with the bulk-terms fix view), Warm-up, Events & sync, Adapters, provider settings with write-only credentials. Demo data matches the boards; `internal/providers/state` and `manage.UsageOf` are the contract other screens read.

## Done so far (W15: remaining adapters, M12)

- Adapters for Mailgun (US/EU, HMAC-signed webhooks with the account signing key read from the API, domain webhooks next to existing URLs, custom sending limit and metrics), SendGrid (signed Event Webhook with ECDSA P-256, checked against SendGrid's test vector; credits, reputation, domain authentication), Resend (100-message batches with idempotency keys, Standard Webhooks/Svix, webhook and suppression APIs, per-domain tracking), SparkPost (existing accounts, idempotent transmissions, basic-auth webhooks, bounce classes, usage and deliverability metrics), Mailjet (50-message batches, basic-auth callbacks, campaign exclusions, statistics counters), Brevo (idempotency keys, bearer-token webhooks, blocked contacts pulled, credits) and Azure Communication Services Email (HMAC or Entra ID, Event Grid handshake and secret header, operation id as message id). - Shared helpers: `apiclient.Exec` and `apiclient.Fanout`, `internal/providers/webhookauth`; the suppression sync turns pull-only for providers that can't take suppressions. Guide: `docs/adapters.md`.

## Done so far (W16: community adapter runtime and SDK)

- The adapter protocol, version 1 (`docs/adapters.md` › Community adapters): signed JSON over HTTP(S) between ReputeCast and an adapter process, with a manifest (capabilities, terms, pricing, connection form, network permissions), one operation per Provider method and optional interface, HMAC-SHA256 signatures on requests and responses with a per-installation secret (sealed, shown once, rotation with a 24-hour grace), idempotency keys derived from the batch, per-operation timeouts and size limits, and error codes that map to provider health.
- `internal/providers/remote`: providers whose method set follows the declared capabilities, a circuit breaker and a concurrency limit per installed adapter, strict answer validation, calls through the same SSRF-guarded client as provider adapters (netguard, `providers.allow_private_networks`), webhooks verified by the adapter at receipt (429 with Retry-After to the provider while it is unreachable) and parsed later with `verified: true`. Installed community adapters of both kinds are registered at startup, after installs, updates and removals (a hook in `manage`) and every 15 seconds in every process: `community:<id>` for remote adapters, `community:<name>` for installed HTTP mappings, which open through `httpgeneric.FromManifest`; code that lists `installed_adapters` rows finds their registry entry with `providers.InstalledKey`. Failures reach provider health like a built-in adapter's (Down · auth failed when the provider rejects the credentials, Down after two failed checks when the adapter process stops answering). A Go fake adapter passes the shared contract suite.
- Operators: `reputecast adapter install|set-url|secret|check|list|remove`, the runtime API for instance admins (`/adapters/{adapterId}/runtime`), `providers.allow_private_networks`, audit entries for every change. The Adapters tab's generic HTTP form gained request headers, webhook authentication and the paths of a custom JSONPath map; saving checks the mapping (`Mapping.Validate`) field by field, problems about fields the form isn't showing appear under it, and "Test with a sample message" renders the request (secrets masked).
- `sdk/adapter-sdk` (`@reputecast/adapter-sdk`, no runtime dependencies): `defineAdapter`, `serve`, `ctx.http` with the network allowlist, webhook helpers, the bounce taxonomy and the contract runner (`npx reputecast-adapter test`). `sdk/adapter-template`: the example-esp adapter from the Adapters board with its manifest, tests, Dockerfile and README; `pnpm install` in `sdk/` builds the SDK the template imports. CI runs the template as a Node process through the Go runtime against the contract suite (`make sdk` locally). Before copies of the template outside this repository can install it, `@reputecast/adapter-sdk` 0.1.0 has to be published to npm.
